# Quick Notes B — друга копія демо для React Host

Той самий код і ті самі ключі сховища, що в `quick-notes`, але інший appId (`dev.yevhen.quicknotes.b`, задано в `.github/workflows/release.yml`). Потрібна для перевірки ізоляції даних між прототипами.

Нотатки зберігаються в IndexedDB (`quick-notes`), незавершена чернетка — у localStorage (`quick-notes:draft`). Унизу екрана видно версію, кількість нотаток, стан мережі та origin, на якому працює застосунок. Зовнішніх залежностей під час виконання немає, тож застосунок працює без мережі.

## Пакет для React Host

```bash
npm run package
```

Команда виконує `tsc` і `vite build`, записує в `dist/` маніфест `react-host.json` і згенеровану `icon.png`, пакує **вміст** `dist/` у `react-host-app.zip` і перевіряє архів тими самими правилами, що й хост ([формат пакета](../../docs/package-format.md)). Пакувальник лежить у `react-host/` — це копія `tools/` з репозиторію хоста (`node tools/vendor-pack.mjs examples/quick-notes/react-host`), тому демо можна винести в окремий репозиторій без змін.

Змінні середовища для тестових варіантів (наприклад, другого застосунку з тими самими ключами сховища):

| Змінна | За замовчуванням |
| --- | --- |
| `RH_APP_ID` | `dev.yevhen.quicknotes` |
| `RH_APP_NAME` | `Quick Notes` |
| `RH_APP_VERSION` | `version` з `package.json` |
| `RH_ICON_COLOR` | `#2563eb` |

## Публікація з окремого репозиторію

React Host пов'язує один репозиторій з одним `appId`, тому демо публікується з власного репозиторію:

1. Створіть публічний репозиторій і скопіюйте в його корінь вміст цієї папки, включно з `.github/workflows/release.yml` і `react-host/`.
2. Змініть `appId` (змінна `RH_APP_ID` або значення за замовчуванням у `scripts/package.mjs`) на власний — він не змінюється між версіями.
3. Підніміть `version` у `package.json`, закомітьте й створіть тег з тим самим номером:

```bash
git tag v0.1.0
```

```bash
git push origin v0.1.0
```

Workflow виконає `npm ci`, збірку, пакування, перевірить, що тег дорівнює `v` + версія маніфесту, і прикріпить `react-host-app.zip` до release.

4. У React Host: «Додати» → `https://github.com/<owner>/<repo>`.

Для перевірки оновлення випустіть наступну версію (`0.2.0`, тег `v0.2.0`) і в меню картки виберіть «Перевірити оновлення». Для перевірки ізоляції опублікуйте другий репозиторій із тим самим кодом і іншим `appId`: обидва застосунки використовуватимуть однакові ключі сховища, але не бачитимуть даних одне одного.
